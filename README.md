# fgstyle Maker

QGISのプロジェクト（`.qgz` / `.qgs`）およびスタイル定義（`.qml` / `.qlr`）から、
MapLibre GL JS で再現できる範囲のシンボル定義を **ForestGeo Studio の `.fgstyle`** に変換するQGISプラグインです。

対応する `.fgstyle` は **定義書 v1**（`_format: forestgeostudio-layer-style` / `_version: 1`）です。

## 1. できること

| 入力 | 対応 |
| --- | --- |
| `.qgz`（圧縮プロジェクト） | ○ 中の `.qgs` を展開して全レイヤを列挙 |
| `.qgs`（プロジェクト） | ○ |
| `.qml`（レイヤスタイル） | ○ 1レイヤとして扱う |
| `.qlr`（レイヤ定義） | ○ 中の `maplayer` を全て列挙 |

| QGISのシンボル化 | `.fgstyle` への変換 |
| --- | --- |
| 単一シンボル | 単色（`fill-color` / `line-color` / `circle-color` ほか） |
| 分類（categorized） | 文字列ルール（`vt-color-rules[].value`） |
| 段階（graduated） | 数値ルール（`num_min` / `num_max`） |
| ルールベース（RuleRenderer） | 単純な条件は色分けルール、複雑な条件は **`case` 式** |
| 非表示（nullSymbol） | 不透明度0（点は半径最小） |
| ポイントクラスタ／変位／逆ポリゴン／地物融合 | 内側のレンダラを取り出して変換（＋警告） |
| データ定義プロパティ（式による上書き） | **MapLibre式へ変換**（色・サイズ・線幅・不透明度） |
| ラベル（simple / rule-based） | `label-*` / `text-*` |
| 縮尺依存表示（レイヤ／ラベル／ルール単位） | `minzoom` / `maxzoom`、`case` 式内のズーム条件 |
| マップ単位の線幅・記号サイズ | **ズーム依存の実寸式**（`interpolate` / `exponential 2`） |
| **破線・点線・一点鎖線・カスタムダッシュ** | **`line-dasharray`（線幅の倍数）へ変換**。区分ごとに違う破線も対応 |
| レイヤ不透明度 | シンボル不透明度へ畳み込み |
| ラスタ | `raster-opacity` ＋ 縮尺依存表示 |
| ベクトルタイル（`.qgz` / `.qml` とも） | `vt-*` 一式。フィルタ式付きスタイルは色分けルールへ、スタイル名は凡例名へ |

### データソースに触らない設計

プロジェクト内の `<maplayer>` 要素を **QML相当の `<qgis>` ドキュメントへ組み替えて、
幾何種別だけを合わせた空のメモリレイヤに `importNamedStyle()` で流し込む** 方式です。

* 実データを一切開かないので、巨大なGeoPackageやネットワーク越しのレイヤでも一瞬で読める
* **データソースが失われた／移動したプロジェクトでも、スタイルだけは救い出せる**
* XMLを手で解釈するのではなく QGIS API のレンダラオブジェクトとして扱うため、QGISのバージョン差に強い

## 2. インストール

1. `fgstyle_maker` フォルダごと、QGISのプラグインディレクトリへ置きます。
   * Windows: `%APPDATA%\QGIS\QGIS3\profiles\default\python\plugins\`
   * Linux: `~/.local/share/QGIS/QGIS3/profiles/default/python/plugins/`
   * macOS: `~/Library/Application Support/QGIS/QGIS3/profiles/default/python/plugins/`
2. QGISを再起動し、`プラグイン → プラグインの管理とインストール` で **fgstyle Maker** を有効化します。
3. ツールバーのアイコン、または `プラグイン → fgstyle Maker` から起動します。

必要環境: QGIS 3.22 以降。

## 3. 使い方

1. **入力** — `.qgz` / `.qgs` / `.qml` / `.qlr` を選び「読み込み」。
2. **変換設定** — 必要に応じて調整（変更すると即座に再変換されます）。
3. **変換対象レイヤ** — 出力したいレイヤにチェック。行を選ぶと右ペインの「JSONのプレビュー」に出ます。
4. **出力** — 出力先フォルダを指定して「選択レイヤを .fgstyle に書き出し」。
   ファイル名は `レイヤ名.fgstyle`（禁止文字は `_` に置換、重複は `_2`, `_3`…）。
5. 「変換レポート」タブで、近似変換した箇所・変換できなかった箇所を確認します。
   Markdown / テキストで保存できます。

### 変換設定

ダイアログの並び順で示します。

| 設定 | 既定 | 意味 |
| --- | --- | --- |
| レイヤの表示縮尺をQGISの設定に合わせる | ON | QGISの「縮尺に応じた表示設定」を `minzoom` / `maxzoom` へ換算（[3.1](#31-縮尺--ズームの換算)）。OFFなら全ズームで表示 |
| ラベル表示をQGISの設定に合わせる | ON | QGISのラベル設定を `label-*` / `text-*` へ変換（[3.2](#32-ラベル表示の変換範囲)）。OFFならラベル関係のキーを出しません |
| **最小線幅 (px)** | **1.0** | QGISの設定がこれより細いとき、この値まで引き上げる（[5.2](#52-単位と細すぎる線)）。0で無効 |
| ルール上限 | 1000 | 1レイヤあたりの色分けルール数の上限。超過分は切り捨てて警告（[3.3](#33-ルール上限)） |
| **条件式に該当がない場合の配色** | **薄いグレー `#cccccc`** | どのルールにも該当しない地物の色（[6.1](#61-qgisの該当なしと-maplibre-の既定値)）。10色のプルダウン＋「その他の色…」で自由に選べます |
| **破線の最小隙間 (px)** | **2.0** | 破線の間隔がこれより狭いとき広げる（[5.3](#53-破線の隙間が狭いと実線に見える)）。0で無効 |
| 凡例表示名をQGISの設定に合わせる | ON | QMLの凡例ラベル／VTのスタイル名を `vt-color-rules[].label` へ。属性値が数字でも、凡例に名称で出せます |
| **分類値の表記ゆれを解消する（全角/半角・前後空白）** | **ON** | 半角化／トリムした別名ルールを追加（[4.1](#41-プラグインが自動で対処するものqgis側の改修は不要)） |
| 条件式に当てはまらない属性値を非表示にする | OFF | 区分のあいだ・上限より上の数値を、前後の配色で埋めずに消す（[6.5](#65-条件式に当てはまらない属性値を非表示にする)） |

#### UIから外した設定（内部で固定しています）

利用者が選ぶ意味が無くなったため、次はUIから削除しました。

| 旧設定 | 固定値 | 理由 |
| --- | --- | --- |
| 解像度 (dpi) | 96 | MapLibre は96dpi基準。mm/pt → px 換算には引き続き使われます |
| 基準緯度 (°) | 35 | 縮尺 ↔ ズーム換算に使用。日本国内では差がごく小さい |
| 基準ズーム | 16 | マップ単位の寸法をズーム依存式で出すようになったため、ほぼ出番なし |
| ズームを整数に丸める | 丸めない | MapLibre は小数のズームを受け付けます |
| 数値属性の扱い | 自動（step式） | 本体側が入力を `to-string` / `to-number` で揃えるので、どれを選んでも結果が同じになりました（[5.1](#51-数値か文字列か)） |
| MapLibre式・rgba色を使う | 常時ON | 本体側が式値をUIプリセット／適用から保護するので、OFFにする理由が無くなりました |
| 該当しない地物を非表示にする | 廃止 | 既定色で描く方針に統一（[6.1](#61-qgisの該当なしと-maplibre-の既定値)） |
| 「すべての他の値」を既定色にする | 常時ON | QGIS側の fallback カテゴリはそのまま既定色として扱います |

> 廃止した「該当しない地物を非表示にする」と、現行の
> **「条件式に当てはまらない属性値を非表示にする」は別物**です。
> 前者は*すべての*非該当地物を消す設定（レイヤ全体が消える事故があったため廃止）、
> 後者は**数値区分のあいだ・上限より上だけ**を消す設定です（[6.5](#65-条件式に当てはまらない属性値を非表示にする)）。

### 3.1 縮尺 ↔ ズームの換算

「レイヤの表示縮尺をQGISの設定に合わせる」がONのとき、QGISの
`レイヤプロパティ → 描画 → 縮尺に応じた表示設定` を次の式でズームへ直します。

```
scale(z) = 156543.03392804097 × cos(基準緯度) × dpi ÷ 0.0254 ÷ 2^z
z = log2( 156543.03392804097 × cos(基準緯度) × dpi ÷ 0.0254 ÷ scale )
```

96dpi・赤道上では `scale(0) ≒ 591,657,528`。緯度35°なら約 `4.85e8` です。
実際の換算値（基準緯度35°・96dpi）:

| QGISの縮尺 | ズーム | | QGISの縮尺 | ズーム |
| --- | --- | --- | --- | --- |
| 1:500,000 | 9.92 | | 1:10,000 | 15.56 |
| 1:100,000 | 12.24 | | 1:5,000 | 16.56 |
| 1:50,000 | 13.24 | | 1:2,500 | 17.56 |
| 1:25,000 | 14.24 | | 1:1,000 | 18.89 |

```
QGIS 1:50000〜1:2500   →  minzoom=13.24 / maxzoom=17.56
QGIS 1:50000〜制限なし →  minzoom=13.24 / maxzoom=24.0
制限なし               →  minzoom=0.0   / maxzoom=24.0
```

* QGISの用語は **最小縮尺＝分母が大きい＝引いた側**、**最大縮尺＝分母が小さい＝寄った側**です。
  大小が逆でも自動で入れ替えます。QGISの `0` は「制限なし」なので `0` / `24` に開放します。
* 値は小数2桁で保持します。整数へ丸めると最大0.5ズーム分、表示開始がずれるためです。
* Web メルカトルは高緯度ほど引き伸ばされるので、厳密には緯度で結果が変わります
  （1:25,000 は緯度35°で `z=14.24`、緯度43°で `z=14.08`）。実用上は無視できる差です。
* 対象キーは、レイヤ本体が `minzoom` / `maxzoom`、ラベルが `text-minzoom` / `text-maxzoom` です。

**OFFにする場面** — QGISでは印刷用に縮尺制限をかけているが、WEBでは常時見せたいとき。
「拡大しても出てこない」レイヤは、たいていこの設定が原因です。

### 3.2 ラベル表示の変換範囲

「ラベル表示をQGISの設定に合わせる」がONのとき、次のキーを書き出します。

```
label-enabled / label-field
text-size / text-color
text-halo-enabled / text-halo-color / text-halo-width
text-minzoom / text-maxzoom      ← 3.1 がONのときだけ
```

| QGIS側 | 結果 |
| --- | --- |
| 単一ラベル（属性名を選択） | ○ そのまま `label-field` |
| 式ラベルだが**単一属性だけ**（`"SPECIES"` など） | ○ 属性名を取り出して変換 |
| ルールベースラベル | △ **先頭の有効ルールのみ**（`.fgstyle` はレイヤに1組だけ）。残りは警告 |
| 複合式ラベル（`concat("A", '-', "B")` など） | × `label-enabled=false`。`label-field` は属性名のみのため |
| 文字の不透明度 | × 警告のみ（`text-opacity` 相当のキーが無い） |
| 配置ルール・回避・引き出し線 | × 警告のみ |

本体は `label-field` から `["to-string", ["get", 属性名]]` を組むので、
属性が数値型でも文字列型でもラベルが出ます。

**OFFにする場面** — 本体側でラベルを設定済みで、変換に上書きされたくないとき。

### 3.3 ルール上限

1レイヤあたりの色分けルール数の上限です。超えた分は**先頭から切り捨てて警告**します。
ベクタ・ベクトルタイルの両方に効きます。

ルール数はそのまま MapLibre の `match` / `step` 式の分岐数になります。地質図のように
数百区分あるスタイルは正常なので既定を 1000 と大きく取っていますが、
**分類フィールドを取り違えた**とき（区分コードではなく個体IDで分類した等）に
数万件のルールが生成され、HTMLが開けなくなるのを防ぐ**保険**です。

警告が出たら、値を上げる前に**まず分類フィールドを確認**してください。
正当に数千区分あるなら最大 10000 まで上げられます。切り捨ては先頭N件なので、
QGIS側でルール順を並べ替えれば残す区分を選べます。

> 凡例は「表示名・色・線種が同じ行」をまとめるので、ルール数がそのまま
> レイヤパネルの行数になるわけではありません。

## 4. 警告の対処区分

**レポートの区分（情報／近似／警告／エラー）が、そのまま「利用者が何をすべきか」を表します。**

| 区分 | 意味 | 必要な対応 |
| --- | --- | --- |
| **情報** | プラグイン側で対処済み | **なし** |
| **近似** | 変換したが見た目が少し変わる | 確認だけ（気になれば設定で調整） |
| **警告** | 変換できていない | **QGIS側の作り直し、または本体側の対応** |
| **エラー** | 変換に失敗し既定値を出力 | 入力の確認 |

### 4.1 プラグインが自動で対処するもの（QGIS側の改修は不要）

> **用語** — 本書の「分類値」は、QGISの分類カテゴリ値やルール条件のリテラル
> （`ser = 619` の `619` など）を指します。変換レポート本文では「判定値」と表記します。

| 事象 | 対処 |
| --- | --- |
| 数値属性と文字列ルールの型不一致 | 分類フィールドの型を判定し、数値なら `step` 式で出力 |
| **分類値の全角英数字・全角空白** | **半角化した別名ルールを同じ色で追加し、両方の表記に当てる** |
| **分類値の前後の空白** | **トリムした別名ルールを追加** |
| **分類値の重複** | **後続の（効かない）ルールを除去（MapLibreと同じ先勝ち）** |
| 全角数字の数値コード | 半角化してから数値として解釈 |
| mm / pt / inch 指定の寸法 | dpi で CSS ピクセルへ換算 |
| マップ単位（メートル）指定 | ズーム依存の実寸式で再現 |
| 細すぎる線幅（0.4px など） | 最小可視幅（既定 1.0px）へ引き上げ |
| **QGISの「非常に細い線」（ヘアライン）** | **幅0でも描画される指定なので最小可視幅へ引き上げ**（[5.2](#52-単位と細すぎる線)）|
| 色のアルファ・シンボル不透明度・レイヤ不透明度 | `*-opacity` へ畳み込み（点は `rgba()` 色へ） |
| QGISで描画されない「該当なし」の地物 | 設定した既定色で描画（[6.1](#61-qgisの該当なしと-maplibre-の既定値)） |
| 複数フィールド・AND/OR のルール条件 | `case` 式へ変換 |
| データ定義プロパティ（式による上書き） | MapLibre式へ変換 |
| ルール／カテゴリ／VTスタイルの凡例名 | `label` キーへ出力（そのまま凡例に出ます） |
| ポイントクラスタ／変位／逆ポリゴン／地物融合 | 内側のレンダラを取り出して変換 |
| **「縁取り＋中心線」の重ね描き（道路記号など）** | **casing レイヤとして再現**（[6.3](#63-縁取りcasingつきの線)）|
| **面の外周線が区分ごとに違う色** | **区分ごとに `outline_color` として出力** |

> 表記ゆれの吸収は、**表記ゆれが実際にあるときだけ**ルールを増やします。
> 通常のデータでは1件も増えません。
>
> 増えた別名ルールは**元のルールと同じ色・同じ凡例名**なので、
> 凡例側（`_build_legend()`）が「表示名も色も同じ行」を1行にまとめます。
> つまり**レイヤパネルの行数はQGISのカテゴリ数と同じまま**です。
>
> ```
> ルール5件（'１２３'/'123'/' ヒノキ '/'ヒノキ'/'456'） → 凡例3行（スギ林／ヒノキ林／その他）
> ```
>
> 増やしたくない場合は「分類値の表記ゆれを解消する」をOFFにしてください（そのときは警告になります）。

### 4.2 設定で挙動を選べるもの

| 事象 | 設定 |
| --- | --- |
| step 式で区分に無いコード値が直前の色になる | 「条件式に当てはまらない属性値を非表示にする」をON |
| 細さをQGISのまま保ちたい | 「最小線幅」を0に |
| QGISの破線の比率をそのまま出したい | 「破線の最小隙間」を0に |
| 該当なしの色を変えたい | 「条件式に該当がない場合の配色」で選ぶ |
| 表記ゆれの別名ルールを増やしたくない | 「分類値の表記ゆれを解消する」をOFF |

### 4.3 QGIS側（またはデータ側）でしか直せないもの

MapLibre に概念が無い／`.fgstyle` に受け皿が無いため、プラグイン側では
**検出して警告するところまで**です。

| 警告 | QGIS側でどうするか |
| --- | --- |
| ジオメトリジェネレータ | バッファ等を実ジオメトリとして書き出してから変換する |
| ダイアグラム（円グラフ等） | 集計結果を属性列として持たせ、色分け・ラベルで表現する |
| ペイントエフェクト（ぼかし・影・グロー） | 効果を使わないシンボルに置き換える |
| 合成モード（ブレンドモード） | 通常合成で成立する配色にする |
| ラベルマスク・引き出し線 | 引き出し線は線レイヤとして別途作る |
| 時系列（Temporal） | 対象期間で絞ったレイヤを分けて出力する |
| SVG／パターン塗り・マーカーライン | 単色に置き換わる。図柄が必要ならスプライト対応（本体側の拡張）が必要 |
| ダッシュ開始位置のオフセット | MapLibre に位相指定が無い。オフセット無しの線種にする |
| ラスタの疑似カラー・パレット・陰影 | 着色済みのラスタ／タイルを書き出してから変換する |
| 分類フィールドが式 | 式の結果を属性列として実体化する（フィールド計算機） |
| データ定義の回転角 | MapLibre の circle に回転が無い。ベクトルタイル＋アイコン運用が必要 |
| 複数シンボルレイヤの重ね描き（縁取り以外） | 先頭1枚に集約される。二重線などはレイヤを分ける |

`.fgstyle` 側の受け皿が無いだけのもの（本体を拡張すれば対応できるもの）は次の2つです。

| 事象 | 本体側で必要な拡張 |
| --- | --- |
| SVGアイコン | `symbol` レイヤへの `icon-image` 出力とスプライト生成 |
| 2.5D（押し出し） | `fill-extrusion` タイプのレイヤ出力 |

## 5. 属性値の型と単位

「変換したのに何も表示されない」「線が細すぎて見えない」の原因はほぼこの2つです。

### 5.1 数値か文字列か

QGISのカテゴリ値や `ser = 619` のような分類値が **数値** のとき、
`.fgstyle` の文字列ルール（`vt-color-rules[].value`）は `"619"` という**文字列**になります。
ところが MapLibre の `match` 式は **型に厳密** なので、
FlatGeobuf / MVT 側で `ser` が数値型のままだと `619`（数値）と `"619"`（文字列）が一致しません。

そこで本プラグインは分類フィールドの型を判定し、数値フィールドは
**`num_min` / `num_max` による数値ルール（step 式）** として出力します（**自動・設定不要**）。
区分に無い値は直前の区分の色になります（「条件式に当てはまらない属性値を非表示にする」で回避できます。[6.5](#65-条件式に当てはまらない属性値を非表示にする)）。

文字列フィールドはこの設定に関わらず従来どおり文字列ルールになります。

> #### 決め手は本体側の入力式
>
> **プラグイン側では FlatGeobuf / MVT の実際の型を確定できません。**
> QGISのプロジェクト定義に書いてあるのは「`Major_Code = 1` という判定式」だけで、
> 書き出したデータで `Major_Code` が整数列なのかテキスト列なのかは別問題です。
> コード値がテキスト列に入っているデータは珍しくありません。
>
> 型セーフ版の本体は `_rule_input_expr()` で入力側を必ず変換します。
>
> | ルール種別 | 入力式 |
> | --- | --- |
> | 文字列 | `["to-string", ["coalesce", ["get", f], ""]]` |
> | 数値 | `["to-number", ["coalesce", ["get", f], -1000000000], -1000000000]` |
>
> これにより `1` でも `"1"` でも同じ結果になります。
> **型不一致は症状が3通りに分かれる**ので、旧版で見分けるときの手掛かりにしてください。
>
> | どこで起きるか | 症状 |
> | --- | --- |
> | `match`（文字列色分け） | どのルールにも一致せず既定色 |
> | `step`（数値色分け） | 実行時エラー → MapLibre の仕様既定値へ落ちる（**全部同じ黒い1px線**になる） |
> | `filter`（破線のレイヤ分割） | 実行時エラーは `false` 扱い → **地物が丸ごと消える** |
>
> 「色分けは効いていないが線は見えていた」状態から破線対応を入れた途端に
> 全部消えるのは、3行目の挙動によるものです。

#### 全角・半角・前後空白

`match` は完全一致なので、分類値とデータの表記が違うと一致しません。
次を検出して具体的に報告します。

| 検出 | 報告例 |
| --- | --- |
| 全角英数記号・全角空白 | `判定値 1 件に全角文字が含まれています` ／ 該当: `'１２３'→'123'` |
| 前後の空白 | `判定値 1 件の前後に空白があります` ／ 該当: `' スギ '` |
| 判定値の重複 | `判定値が重複しています（先に書かれた方だけが有効）: スギ` |

数値ルールへ変換するときは、全角数字（`１２３`）を半角に直してから解釈します。
それでも数値として読めない値が混じっていれば、文字列ルールへ戻して警告します。

### 5.2 単位と細すぎる線

QGIS の寸法単位は **mm / pt / inch / ピクセル / マップ単位** のいずれかです。
`.fgstyle` の太さ・サイズは単位表記を持ちませんが、**実体は MapLibre の CSS ピクセル**
（`_build_html()` が `paint` へ素通しするため）です。したがって

| QGIS側 | 換算 |
| --- | --- |
| Pixel | そのまま（1:1） |
| MM | `値 × dpi ÷ 25.4`（96dpiなら ×3.7795） |
| Point | `値 × dpi ÷ 72`（96dpiなら ×1.3333） |
| Inch | `値 × dpi` |
| MapUnit / MetersInMapUnit | ズーム依存の実寸式（[7章](#7-高度な表現maplibre式)）。式OFFなら基準ズームでの固定px |

**ForestGeo Studio 側がポイント扱いになっている、といった齟齬はありません。**
どの単位で書かれた値がどのピクセル値になったかは、レポートの「単位」項目に
`QGIS側の寸法指定と換算結果: Pixel 0.4 → 0.4px / Pixel 1.2 → 1.2px` の形で出ます。

問題は換算ではなく **絶対値** です。QGIS はサブピクセル幅の線をヘアライン
（実質1デバイスピクセル）として描くので画面では見えますが、MapLibre は
`line-width: 0.4` を指定どおり細く描くため、ほぼ消えます。
そこで **最小線幅（既定 1.0px）** を下回る幅を引き上げ、何をどう変えたかを報告します。

#### 「非常に細い線」と「線なし」は別物

QGISのストローク幅を `0` にすると、幅の欄には **「非常に細い線」** と表示されます。
これは**線を消す指定ではなく、1デバイスピクセルのヘアラインとして描く**指定です。
線を消すときは幅ではなく**線種**を「線なし」にします。

| QGIS側 | 意味 | 変換 |
| --- | --- | --- |
| 幅 `0` ＋ 線種 実線／破線など | ヘアライン（**描画される**）| **最小線幅（既定 1.0px）へ引き上げ** |
| 線種「線なし」(`outline_style="no"`) | 線なし（描画されない）| `line-width: 0`・不透明度0のまま |

MapLibre の `line-width: 0` は文字どおり何も描かないので、前者をそのまま渡すと
**QGISでは見えていた枠線がWEBでは消えます**。v0.7.1 でこれを区別するようにしました。

* 元の細さを保ちたい場合は最小線幅を `0` にしてください（ヘアラインも0のままになります）。

### 5.3 破線の隙間が狭いと実線に見える

MapLibre の `line-dasharray` は **線幅の倍数** で解釈されます。ここから2つの問題が出ます。

#### ① 線幅を引き上げると破線の実寸も一緒に伸びる

QGIS のカスタムダッシュは**絶対長（mm / px）**です。倍数へ直すときに線幅で割るので、
その後で線幅が変わると実寸がずれます。

```
QGIS:  線幅 0.4px / ダッシュ 4px・2px
  → 倍数へ: 4 / 0.4 = 10、2 / 0.4 = 5        …… [10, 5]
  → 最小線幅で 0.4px → 1.0px へ引き上げ
  → MapLibre の実寸: 10 × 1.0 = 10px、5 × 1.0 = 5px   ← 2.5倍に伸びる
```

**v0.5.2 以降は最終線幅を基準に倍数を組み直します**（上の例なら `[4, 2]` → 実寸 4px/2px）。
Qt の既定パターン（破線・点線・鎖線）は元から線幅の倍数なので組み直しません。

#### ② 隙間が 2px 未満だと実線に見える

MapLibre は線の縁を必ずアンチエイリアスし、**これは破線の切れ目にも適用されます**。
そのため隙間が 2px 程度を下回ると、両側のダッシュのにじみが重なって切れ目が消えます。
QGIS（Qt）は切れ目を鋭くラスタライズするので、**同じ数値でも QGIS では点線に見え、
WEB では実線に見える**という食い違いが起きます。

```
産総研シームレス地質図V2（線）伏在断層
  QGIS:      線幅 1.2px / ダッシュ 4.5px・隙間 1.5px   → 点線に見える
  MapLibre:  同じ指定                                 → ほぼ実線に見える
```

**破線の最小隙間（既定 2.0px）** を下回る隙間を、**線分の長さは変えずに**広げます。

| | 線分 | 隙間 | dasharray |
| --- | --- | --- | --- |
| QGIS（伏在断層） | 4.5px | 1.5px | `[3.75, 1.25]` |
| 変換後 | 4.5px | **2.0px** | `[3.75, 1.667]` |
| QGIS（推定断層） | 7.0px | 3.0px | `[5.833, 2.5]` |
| 変換後 | 7.0px | 3.0px | `[5.833, 2.5]`（下限を満たすので不変） |

線分の長さを触らないので、**「短い破線＝伏在／長い破線＝推定」という区分どうしの
見分けは QGIS と同じまま**残ります。QGIS の比率をそのまま出したい場合は `0` にしてください。

> 隙間をもっと開けたい場合は、この値を `2.5`〜`3.0` に上げます。
> 逆に線を太くすると（最小線幅を上げると）隙間も比例して広がるので、
> そちらで調整することもできます。

## 6. 変換の考え方

### 6.1 QGISの「該当なし」と MapLibre の「既定値」

QGISは、分類・段階・ルールベースのいずれでも **どの区分にも当てはまらない地物を描画しません**。
一方 MapLibre の `match` / `step` / `case` 式は **必ず既定値へフォールバック** します。
この差は消せないので、**該当なしは既定色で描く**ことを原則にしています。

* 色は変換設定の **「条件式に該当がない場合の配色」**（既定は薄いグレー `#cccccc`）で決めます。
* QGIS側に「すべての他の値」カテゴリや ELSE ルールがあれば、**そちらの色が優先**されます。
* ベクトルタイルでフィルタ無しのスタイルが1つも無い場合も同じ扱いです。

> 以前のバージョンには「該当しない地物を非表示にする」（既定の不透明度を0にして消す）
> 設定がありましたが、廃止しました。理由は2つです。
>
> * 区分ごとに不透明度・線幅を全ルールへ書き戻す必要があり、数百区分のスタイルで
>   `.fgstyle` が無駄に膨らむ
> * 属性の型不一致などで1件も一致しなかったとき、**レイヤ全体が消えて原因が分からない**
>
> 既定色で描いておけば「該当なしがどれだけあるか」が地図上で見えるので、
> データ側の問題にも気づけます。

### 6.2 ベクトルタイルの扱い

QGISのベクトルタイルは `<renderer type="basic">` の下に、
**ソースレイヤ名・幾何種別・フィルタ式**を持つスタイルが並ぶ構造です。

```xml
<renderer type="basic">
  <styles>
    <style layer="全国森林資源メッシュ" geometry="2" name="スギ"
           expression="&quot;森林簿樹種1&quot; IS 'スギ'"> … </style>
    …
  </styles>
</renderer>
```

変換の対応は次のとおりです。

| QGIS側 | `.fgstyle` |
| --- | --- |
| `layer`（ソースレイヤ名） | `vt-source-layer` |
| `geometry`（0/1/2） | `vt-geom-type`（Point / LineString / Polygon）|
| フィルタ式が**空**のスタイル | 既定のスカラー値（`fill-color` など）|
| フィルタ式が**ある**スタイル | `vt-color-rules` の1行 |
| `name`（スタイル名） | `vt-color-rules[].label`（凡例表示名）|
| 各スタイルのシンボル | 色・幅・不透明度・線種 |

* フィルタ式は `=` のほか **`IS`**（ベクトルタイルの既定）・`IN`・範囲比較を解釈します。
* `.fgstyle` は **1レイヤにつきソースレイヤ1つ・幾何種別1つ**なので、複数組ある場合は
  スタイル数が最も多い組だけを出力し、残りを警告します（定義書 9.1）。
* フィルタ無しのスタイルが1つも無い場合、該当なしは[6.1](#61-qgisの該当なしと-maplibre-の既定値)の既定色になります。

> `.qml` 単体には `<maplayer type="vector-tile">` が無いため、
> **`<renderer type="basic">` + `<styles><style layer=…>` という形でベクトルタイルと判定**します。
> v0.6.0 以前はこれを見落として「単一シンボル」として読み込んでいたため、
> 色分けが丸ごと落ちていました。

### 6.3 縁取り（casing）つきの線

道路記号のように「太い線の上に細い線を重ねて縁取りを作る」表現は、
QGISでは**同じ条件のスタイルを2枚重ねる**か、**1つのシンボルに複数の
SimpleLine を積む**かで作ります。

```
edges_1_casing   N13_003 IS 1   幅4.5px  #675f80   ← 下に敷く縁取り
edges_1_inner    N13_003 IS 1   幅3.0px  #6abc6e   ← 上に描く中心線
```

QGISは定義順に描く（後が上）ので、**いちばん上が中心線**、その下でいちばん太い
ものが縁取りです。v0.7.1 以前はこれを「分類値の重複」として後ろを捨てていたため、
**縁取りだけが残って中心線の色が失われていました**（道路が全部くすんだ紫の太線になる）。

v0.8.0 では次のように変換します。

| QGIS側 | `.fgstyle` |
| --- | --- |
| 中心線（いちばん上） | `vt-color-rules[].color` / `width` |
| 縁取り（下でいちばん太い） | `vt-color-rules[].casing_color` / `casing_width` |
| レイヤ既定の縁取り | `line-casing-color` / `line-casing-width`（VTは `vt-line-casing-*`）|

本体は `{レイヤID}_casing` という line レイヤを**本線の下に**差し込みます。
縁取りを持たない区分は幅0になるので何も描かれません。

> 上に重ねたほうが太い場合は縁取り構成ではないと判断し、
> 従来どおりいちばん上の1枚だけを変換して近似として報告します。

### 6.4 近似変換される主なもの

| QGIS側 | 変換結果 |
| --- | --- |
| グラデーション塗り／シェイプバースト | 2色の中間色（単色） |
| ハッチング・SVG・点／線パターン塗り | ベタ塗り |
| 円以外のマーカー形状、SVG／フォントマーカー | 円 |
| 複数シンボルレイヤ | 先頭の1枚のみ |
| 太字／斜体 | Open Sans Regular 固定 |
| マーカーの回転、線オフセット、矢印 | 変換されない（警告） |
| ラスタの疑似カラー／パレット／陰影 | 変換されない（着色済みタイルの書き出しが必要） |

### 6.5 条件式に当てはまらない属性値を非表示にする

既定は **OFF** です。数値で色分けしたレイヤにだけ効きます。

分類フィールドが数値のとき、`.fgstyle` は `num_min` / `num_max` のルールを出し、
本体は MapLibre の **`step` 式**を組みます。`step` は「しきい値以上・次のしきい値未満」で
値を決める階段関数で、**上限を持ちません**。ここが QGIS との差になります。

| | QGISの分類レンダラ | MapLibre の `step` |
| --- | --- | --- |
| 区分に無い値 | 描かない | **直前の区分の色で塗る** |
| 最後の区分より大きい値 | 描かない | **最後の色で塗り続ける** |

#### OFF（既定）— コード 1, 2, 4, 7 で色分けした例

```json
["step", ["to-number", ["coalesce", ["get","CODE"], -1000000000], -1000000000],
  "#cccccc",  1, "#ff4b00",  2, "#005aff",  4, "#03af7a",  7, "#f6aa00"]
```

| CODE | 色 | 不透明度 | 見え方 |
| --- | --- | --- | --- |
| 1 | `#ff4b00` | 1.0 | 描かれる |
| 2 | `#005aff` | 1.0 | 描かれる |
| **3** | `#005aff` | 1.0 | 描かれる ← 区分外なのにヒノキの青 |
| 4 | `#03af7a` | 1.0 | 描かれる |
| **5, 6** | `#03af7a` | 1.0 | 描かれる ← 区分外なのに広葉樹の緑 |
| 7 | `#f6aa00` | 1.0 | 描かれる |
| **9** | `#f6aa00` | 1.0 | 描かれる ← 最終区分より大きいのに橙 |

#### ON — 不可視のダミー区分を挿し込む

区分と区分のあいだ、および最終区分の上に **不透明度0** のルールを追加します。
ルールは4件から7件になります。

```
num_min=1  color=#ff4b00                  スギ
num_min=2  color=#005aff                  ヒノキ
num_min=3  color=#005aff  opacity=0.0     ← 挿入
num_min=4  color=#03af7a                  広葉樹
num_min=5  num_max=6  color=#03af7a  opacity=0.0   ← 挿入
num_min=7  color=#f6aa00                  その他
num_min=8  color=#f6aa00  opacity=0.0     ← 挿入（上限側）
```

結果、3・5・6・9 が**描かれなくなり**、QGISと同じ見た目になります。
色はそのままで、**不透明度だけを0にして消しています**
（色キーに `rgba(0,0,0,0)` を入れるより、凡例やレイヤ複製で扱いやすいため）。

#### 挿入される条件

次の3つを全部満たすときだけ挿入します。

1. 前後の区分値が**どちらも整数**（＝コード分類）
2. 差が **2以上**
3. 最終区分が整数なら、その `+1` 以上を消す区分を必ず1件足す

したがって、樹高 0–5 / 5–10 / 10–15 のような**連続量の等間隔分類には何も挿入されません**。
効くのは**整数コードで飛び番がある**分類（樹種コード・地質コード・地目コードなど）だけです。

#### 「条件式に該当がない場合の配色」との守備範囲の違い

| 属性値 | 既定色（[6.1](#61-qgisの該当なしと-maplibre-の既定値)） | 本設定 |
| --- | --- | --- |
| 最初の区分より小さい（0, −5 など） | ✅ 既定色で描画 | 同左（変わらない） |
| 属性が無い／空／文字列 `"abc"` | ✅ 既定色で描画 | 同左（変わらない） |
| 区分の**あいだ**（3, 5, 6） | ⚠️ 直前の色で描画 | ✅ 非表示 |
| 最終区分より**大きい**（9） | ⚠️ 最後の色で描画 | ✅ 非表示 |

つまり本設定は、**既定色ではカバーできない「区分のあいだ・上限より上」だけ**を塞ぐ補完機能です。

#### 既定をOFFにしている理由

* ルール数が増える（上の例で4件→7件）。飛び番の多い地質図では倍近くになり、
  [ルール上限](#33-ルール上限)にも近づきます
* 塞ぎ方が「非表示」なので、**そこだけデータの異常が見えなくなります**

QGISの分類レンダラは通常データに実在する値だけを列挙するので、OFFのままでも
「区分外の色で塗られる」は現場ではまず起きません。ONにして地物が消えた場合、
それは不具合ではなく **QGISの分類に無いコードを持つ地物が実在した**という発見です。
本筋の対処は、QGIS側の分類に区分を追加することになります。

## 7. 高度な表現（MapLibre式）

`.fgstyle` のスカラーキー（`fill-color` / `circle-radius` / `line-width` / `text-size` など）は、
本体の `_build_html()` が **MapLibre の paint / layout へ `json.dumps` でそのまま流し込みます**。
つまり値に **MapLibre式（JSON配列）や `rgba()` 色** を入れれば、
ForestGeo Studio のUIに項目が無くてもWEB地図には反映されます。

この仕組みは**常時有効**です（設定項目はありません）。次が自動的に使われます。

| できること | 出力例 |
| --- | --- |
| **複雑なルール条件**（複数フィールド・AND/OR・IN・BETWEEN） | `fill-color` に `["case", cond, color, …, default]` |
| **データ定義プロパティ**（式による色・サイズ・線幅の上書き） | `circle-radius` に `["*", ["get","樹高"], 0.5]` など |
| **マップ単位の実寸**をズーム全域で正しく再現 | `["interpolate", ["exponential",2], ["zoom"], 0, a, 24, b]` |
| **カテゴリごとの円の半径・縁取り色**（色分けルールでは不可） | `circle-radius` に `["match", …]` |
| **点シンボルの不透明度**（対応キーが無い） | `circle-color` に `"rgba(230,57,70,0.6)"` |
| **ルール固有の縮尺範囲** | `case` の条件に `[">=", ["zoom"], 13.24]` を畳み込み |

### 7.1 QGIS式 → MapLibre式トランスレータ

`converter/mlexpr.py` が、1地物だけを見て評価できる式を変換します。

| 対応 | 例 |
| --- | --- |
| 比較 | `=` `<>` `!=` `<` `<=` `>` `>=` |
| 論理 | `AND` → `all` / `OR` → `any` / `NOT` → `!` |
| 集合・範囲 | `IN` / `NOT IN` / `BETWEEN` / `IS NULL` / `IS NOT NULL` |
| 算術 | `+ - * / % ^`（`^` は右結合）、単項マイナス |
| 文字列 | `\|\|`、`concat` `upper` `lower` `length` `substr`（1始まり補正） |
| 型変換 | `to_string` `to_real` `to_int` |
| 数学 | `abs` `round`(桁指定可) `floor` `ceil` `sqrt` `ln` `log10` `exp` `min` `max` |
| 制御 | `CASE WHEN … THEN … ELSE … END`、`if()`、`coalesce()` |
| その他 | `$id`、引用符あり／なしのフィールド参照（日本語可） |

変換できないもの（明示的に理由を報告します）:
ジオメトリ関数（`$geometry` `area` `buffer` …）、集計関数（`sum` `aggregate` …）、
正規表現、日時関数、他レイヤ参照、変数（`@…`）、ワイルドカード付き `LIKE`。

### 7.2 単純な条件は式にしない

**単一フィールド・単一モードで表現できるルールは、従来どおり `vt-color-rules` として出力します。**
そのほうが凡例が素直に出るためです。式（`case`）に切り替えるのは、
複数フィールド・AND/OR・ルール固有の縮尺範囲など、色分けルールでは表現できない場合だけです。

式パスに切り替わったときは、凡例を **`vt-legend`** キーへ別途書き出します。

## 8. ForestGeo Studio 本体との対応

本プラグインの出力は、**現行の ForestGeo Studio 本体でそのまま動きます**。
利用者が何か追加で当てるものはありません。

以前のバージョンでは「本体パッチA〜D」という表示をレポートに出していましたが、
それらは本体へ取り込み済みのため**廃止しました**。参考までに何が入っているかだけ書いておきます。

| 本体側の仕組み | 何のためか |
| --- | --- |
| `sanitize_style_for_ui()` / 式値の退避・復元 | MapLibre式・`rgba()` 色を含むスタイルを、UIのプリセットや「適用」で壊さない |
| `_rule_input_expr()` | 色分け・幅・フィルタの入力を `to-string` / `to-number` で型変換し、属性が数値でも文字列でも一致させる（[5.1](#51-数値か文字列か)） |
| ルール表の「凡例表示名」「線種」列 | `label` / `dasharray` をUIで編集・保存できる |
| ルール表の未知キー保持 | `casing_*` / `outline_color` など、UIに列が無いキーが「適用」で失われない |
| `_build_legend()` の `vt-legend` 対応 | 式でスタイルを組んだ場合の凡例を直接指定できる |
| `_build_casing_layer()` | 縁取り（casing）レイヤを本線の下に敷く（[6.3](#63-縁取りcasingつきの線)） |

> **古い本体を使っている場合**は、色分けが効かない・凡例が分類値のまま・
> 破線が反映されない、といった症状が出ます。その場合は本体を更新してください。

## 9. 互換性一覧

添付いただいた互換性調査レポートの区分に対する、本プラグインの実装状況です。

### 完全対応（レポート §11）

| 機能 | 状態 |
| --- | --- |
| Single Symbol / Categorized / Graduated | ○ |
| Basic Rule | ○ |
| Fill / Line / Circle | ○ |
| Color / Opacity / Width | ○（点の不透明度は rgba 色として） |
| Basic Label / Halo | ○ |
| Scale Dependent Rendering | ○（レイヤ・ラベル・ルールの3階層） |

### 条件付き（レポート §4）

| 機能 | 状態 |
| --- | --- |
| Rule-based Renderer | ○ 単純な条件は色分けルール、複雑な条件は `case` 式 |
| Data Defined Override（色・サイズ・透明度） | ○ 式トランスレータ経由 |
| Data Defined Override（回転） | × MapLibre の circle に回転の概念がない |
| QGIS Expression Translator | ○ [7.1](#71-qgis式--maplibre式トランスレータ) |

### 近似（レポート §5）

| 機能 | 状態 |
| --- | --- |
| SVG シンボル / Pattern Fill | △ 単色へ縮退（スプライト生成は未実装） |
| Label Background | × 検出して警告 |
| 2.5D | × `.fgstyle` に `fill-extrusion` の口が無い |

### 非対応（レポート §7・§9）— 検出して警告します

Geometry Generator / Paint Effect（Blur・Glow・Drop Shadow・Inner Shadow・Colorize・Transform）/
Blend Mode / Diagram / Label Mask / Callout / Temporal。

いずれも `converter/features.py` がプロジェクトXMLから検出し、
「なぜ変換できないか」と「代替手段があるか」をレポートに出します。

### レポートとの相違点

* **Graduated → `interpolate`**: 採用していません。QGISの段階分類は離散クラスなので
  `step` が正しく、`interpolate` にすると中間色が発生してQGISと見た目が変わります。
* **SVG → スプライト**: 本体の `_build_html()` が `symbol` レイヤに `icon-image` を
  出力しないため、`.fgstyle` の範囲では実現できません。本体側の対応が要ります。
* **中間表現(IR)**: レポート §12 の構成に近い形で、`SymbolProps`（シンボル属性）＋
  MapLibre式という2層にしています。QGIS APIのオブジェクトをそのまま扱えるため、
  独自IRを挟むより実装量が小さく、QGISのバージョン差にも強くなります。

## 11. 既知の制限

| # | 内容 |
| --- | --- |
| 1 | ラスタは配色を変換しません。不透明度と縮尺依存表示のみです |
| 2 | ベクトルタイルは1レイヤにつきソースレイヤ1つ・幾何種別1つだけ出力します（`.fgstyle` の制約） |
| 3 | ダイアグラム、2.5D、ヒートマップ、SVGスプライトは変換対象外です（検出して警告） |
| 4 | ルールベースの入れ子ルールは展開しません |
| 5 | 線パターン（マーカーライン・ハッチライン）は単色の実線に置き換わります。破線・点線は `line-dasharray` へ変換されます |
| 6 | 段階分類の `num_max` は凡例表示専用です。実際の区間上限は次の区分の `num_min` で決まります（定義書 付録B #1） |
| 7 | 現在QGISで開いているプロジェクトの直接変換には未対応です（いったん保存してから読み込んでください） |
| 8 | 出力には現行の ForestGeo Studio 本体が必要です（古い本体では色分け・破線・凡例が反映されません） |
| 9 | 数値属性を step 式で出す既定モードでは、区分に無いコード値が直前の区分の色になります（「条件式に当てはまらない属性値を非表示にする」で解消） |
| 10 | 属性の型はQGISのカテゴリ値・判定リテラルから推定します。同じ列に数値と文字列が混在するデータでは推定を外すことがあります |
